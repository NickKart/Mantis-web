# Mantis Web – видеоаналитика витрины в браузере

Mantis считает по видео с камеры, сколько людей прошло мимо витрины, притормозило, посмотрело на неё, вернулось к ней и зашло в магазин. Нейросеть работает прямо в браузере на видеокарте (WebGPU) или процессоре (WASM) – видео никуда не отправляется. Статистика – в Firebase, общая с приложениями для iPhone и Mac.

Интерфейс сделан по макету `mantis-prototype8` (Preact, `src/app/`); ядро – движок подсчёта, камеры, план точки, облако, мост IP-камер – прежнее (`src/engine`, `src/multi`, `src/twin`, `src/cloud`, `bridge/`).

## Разделы

- **Как начать работать** – три шага по настоящему состоянию: камера размечена → подсчёт запущен → данных хватает (от 30 прохожих). Ссылки на Mantis Агент для IP-камер.
- **Live** – что происходит у витрины сейчас: «Реалистичное видео» (кадр с рамками: голубая – прошёл мимо, жёлтая – посмотрел, красная – остановился) и «Схематичное видео» (люди на плане точки, слои Тепло / Следы / Зоны / Камеры / Скорость). Справа – «Сейчас у витрины», счётчики за сегодня (с «Вернулись»), камеры (видео можно скрыть). Кнопки: записать фрагмент, на весь экран, запустить / остановить подсчёт.
- **Настройка камеры** – список камер, план точки и проверка на видеофайле. Мастер камеры: **Источник** (камера компьютера / USB, IP-камера через мост, видеофайл) → **Разметка кадра** (где витрина, зона витрины, линия прохода, вход, чувствительность; сохраняется сама) → **Проверка** (живой кадр с отброшенными рамками и причинами, уровень, строгость, минимальный рост, зоны исключения, неподвижные фигуры, оценка кадра) → **На план** (привязка по полу или по сектору, можно позже). Видеофайл: разметка → анализ 5–15 кадров/с → итоги, выгрузка JSON/CSV, сохранение в «Записи».
- **Аналитика** – воронка за сегодня / 7 / 30 дней / свой период с изменением к прошлому такому же периоду (в час наблюдения), «Вернулись к витрине», по часам, по дням недели, «Главное за период» (автовыводы), оценка выручки по профилю точки, конверсия по чекам из кассы, отчёт PDF (печать страницы). Оформления витрины («Витрина «Ноябрь» с 28 октября») задаются здесь же. Без данных – «Показать на примере».
- **Дополнительная аналитика** – A/B: две записи или два периода (оформления витрины, последние / предыдущие 7 или 30 дней, свой период). Вывод, проверка корректности (поток, дни недели, объём), таблица долей, сохранение сравнения, отчёт для клиента.
- **Записи** – фрагменты в графическом режиме (без видео): люди на плане, счётчики на момент, отметки «зашёл» на шкале, тепло, скорость ½–4×, переименование и удаление.
- Внизу меню: **Поиск ⌘K** (разделы, камеры, записи, действия), **профиль** (вход, точка, средний чек и конверсии, личный кабинет в облаке, код точки, автозапуск Агента) и блок **Система** (нейросеть GPU/CPU, кадров в секунду, синхронизация облака).

### Метрика «Вернулись»

Человек ушёл вперёд дальше порога (5% ширины кадра или полроста), развернулся, прошёл назад не меньше порога и снова оказался в зоне витрины – засчитывается один раз (`src/engine/session.ts`, тесты `tests/returned.test.ts`). Поле `returned` пишется в почасовую статистику Firestore (`users/{uid}/hours`) и в живой кабинет (`turned`); iOS это поле пока не пишет. Людям на плане и в записях ставятся отметки «вернулся» и «зашёл».

### Настройки веб-версии в облаке

`users/{uid}/web/settings` – оформления витрины, чеки из кассы, сохранённые сравнения (то, чего нет в iOS). Без входа – только в браузере.

## Запуск

```bash
cd web
npm install
npm run dev          # http://localhost:5173
```

Сборка для размещения на сайте:

```bash
npm run build        # результат в dist/ – обычные статические файлы
npm run preview      # проверить сборку локально
```

`dist/` можно выложить на любой статический хостинг: nginx, S3, GitHub Pages и т. п. Сборка весит около 40 МБ, из них 27 МБ – WASM-рантайм нейросети и 12 МБ – модель. Браузер скачивает их один раз и кэширует.

Чтобы на процессоре работали несколько потоков, сервер должен отдавать заголовки:

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Без них всё тоже работает, но на процессоре в один поток, то есть медленнее. Для WebGPU заголовки не нужны. `npm run dev` и `npm run preview` отдают их сами.

## Мониторинг: подсчёт на месте часами и днями

> В новом интерфейсе: камеры, разметка, чувствительность и план – «Настройка камеры»; запуск, живой кадр и живой план – «Live»; статистика – «Аналитика». Ниже – как работает ядро.

Раздел «Мониторинг» – три шага в порядке работы: **1 · Камеры** (добавить камеры, перетаскиванием поменять местами, чувствительность, «Настроить» в карточке камеры: название, псевдоним, цвет, где витрина, зона витрины и привязка к плану) → **2 · План** (план точки, магазин, витрины, входы, штендеры, стеллажи и витрины-прилавки внутри магазина или на плане, зоны; сохраняется сам) → **3 · Мониторинг** (запуск, камеры над планом – нажмите, чтобы открыть на весь экран, живой план, итоги с запуска). «Быстрый показ» – одна камера без плана в разделе «Анализ».

Мониторинг превращает ноутбук или мини-ПК в постоянный датчик у витрины – сразу на нескольких камерах, как в Mantis для Mac: встроенная, USB и IP-камеры (через мост или Mantis Агент). Экран один и тот же в браузере, у Агента и в приложении для Windows.

1. Войдите тем же аккаунтом, что в iOS-приложении, или зарегистрируйтесь. Без входа всё работает, но статистика остаётся только в этом браузере.
2. «Добавить камеру» → разметьте кадр каждой камеры (зона, линия, вход, где витрина) → «Запустить пилот».
3. Оставьте вкладку открытой на экране, ноутбук – на зарядке. Кнопка «Во весь экран» убирает лишнее.

Камеры показываются сеткой (Авто / Крупно / Средне / Мелко / Мини), клик по камере – на всё окно. У каждой камеры – свои итоги за сегодня и своя **чувствительность** (окно с живым кадром, как на Mac):

- уровень – порог уверенности нейросети и сколько секунд человек должен пробыть в зоне;
- минимальный рост фигуры (отсекает мелких людей далеко на улице и отражения);
- зоны исключения – обвести манекен, плакат, зеркало, телевизор: всё внутри не считается, углы тянутся прямо на кадре;
- неподвижные фигуры – кто стоит без движения дольше N минут, перестаёт считаться, его место запоминается; найденные места можно одной кнопкой сделать зонами исключения;
- строгость «посмотрел / притормозил» (мягкая / обычная / строгая);
- режим проверки: на кадре видно, что считается, что отброшено и почему («уверенность 28%», «мала», «зона исключения», «неподвижна»).

Если раньше был настроен пилот на одну камеру, его камера и разметка сами переносятся в первую камеру сетки.

Что делает пилот:

- считает без остановки и раскладывает прирост по часам: люди в зоне, прошли, посмотрели, притормозили, зашли, секунды наблюдения;
- раз в минуту отправляет изменённые часы в Firestore `users/{uid}/hours/{2026-10-14-12}` – в том же формате, что iOS (`HourStat`), поэтому статистика видна и на вкладке «Статистика», и в приложении на iPhone;
- без интернета копит данные в браузере и отправляет, когда связь вернётся;
- раз в минуту пишет пульс в `users/{uid}/devices/{id}`: работает ли точка, кадров в секунду, итоги за сегодня – это видно на вкладке «Статистика»;
- не даёт экрану погаснуть (Wake Lock), сам перезапускает камеру и нейросеть при сбое, после перезагрузки страницы продолжает подсчёт сам;
- не копит память: ушедшие люди забываются, остаются только счётчики.

Вкладка «Статистика» повторяет экран статистики iOS: итоги за 7/30 дней или всё время, час пик, лучший день недели, графики по часам, дням недели и датам, оценка витрины и пересчёт в деньги по профилю точки (средний чек и конверсии задаются в окне аккаунта).

Правила Firestore те же, что для iOS (`users/{uid}/{document=**}` – только владелец). Если сайт будет открываться не с `localhost`, добавьте его адрес в Firebase Console → Authentication → Settings → Authorized domains.

Ограничения пилота:

- если один и тот же час считают сразу два устройства под одним аккаунтом, в облаке останется больший из двух счётов (так устроено объединение в iOS). Для пилота на нескольких точках пока заводите отдельный аккаунт на точку;
- в фоновой вкладке браузер может замедлить подсчёт – держите вкладку на экране;

## Цифровой двойник

> В новом интерфейсе план редактируется в «Настройке камеры» → «План точки», живой план – вкладка «Схематичное видео» на экране Live. Раздела «Демо» в новом интерфейсе нет (на экране «Аналитика» есть «Показать на примере»).

Шаг «3 · Мониторинг» – план точки в метрах (магазин и улица перед ним), на котором видно людей со всех камер пилота в реальном времени. Порт раздела «Двойник» из Mantis для Mac, данные те же.

- **План и зоны.** Размеры плана, подложка (картинка плана, яркость), магазин любой формы (углы тянутся, «+» на стороне добавляет угол), витрины и входы на стенах магазина, выносные штендеры с поворотом, зоны (касса, стеллажи, витрина снаружи…).
- **Привязка камер.** По полу – 4 точки в кадре и те же точки на плане (гомография); сетка пола, стены, витрины и зоны ложатся поверх кадра для проверки. По сектору – для камер, которые не видят пол: место, поворот, угол обзора и дальность, расстояние до человека – по его росту в кадре. На плане видно сектор обзора камеры и расстояние до витрины.
- **Живой план.** Ноги людей переводятся в координаты плана, человек с нескольких камер сливается в одну точку; цвет – идёт / притормозил / смотрит на витрину; следы, скорость (м/с), число людей в каждой зоне.
- **Статистика дня:** тепловая карта, заходы и среднее время в зонах, пик и число людей. Хранится в этом браузере (только координаты и счётчики, без картинок).
- **Демо** – отдельный раздел меню: **1 · План** (свой план демо – магазин, витрины, входы, штендеры, стеллажи и витрины внутри магазина, зоны и придуманные камеры: «Добавить камеру», место, поворот, угол и дальность тянутся на плане; в первый раз копируется из мониторинга, кнопка «Взять план мониторинга»), **2 · Демо** – синтетические прохожие ходят по улице, обходят штендеры, останавливаются у витрины, заходят через дверь, ходят между стеллажами и останавливаются у них; тепло, зоны, сколько людей сейчас в кадре каждой камеры и сколько она видела за запуск, запись в «Записи». В статистику не идут, план мониторинга не меняется. Для показа клиенту.
- **Окно камер** – пока идёт пилот, камеры видны в плавающем окне поверх плана (все сеткой или одна), окно двигается, меняет размер, разворачивается.
- **Видео.** «Видео…» – готовый ролик разбирается прямо здесь: привязка к плану, анализ, затем видео (с рамками) и план идут синхронно, тепло и зоны – за ролик до текущего момента. После анализа в разделе «Анализ» есть кнопка «Цифровой двойник» – без повторного анализа.

## Цифровой двойник в облаке и личный кабинет

Как приложение на iPhone (`TwinPublisher.swift`): пока вы вошли в аккаунт, страница раз в секунду перезаписывает состояние точки в Firebase Realtime Database (`jinpix-ac93d-default-rtdb`, europe-west1), а личный кабинет (`cabinet.html`) показывает его вживую.

- `live/{uid}/{точка}` – `meta` (устройство, `platform: "web"`, статус «идёт подсчёт / на связи / нет связи»), `today` (за сегодня по всем камерам), `cameras` (по каждой: считает ли, к/с, в кадре, за сегодня), `people` (ноги в кадре и примерное место на полу от камеры), `plan` (люди на плане точки, м; один человек с нескольких камер – одна точка).
- `presence/{uid}/{точка}/{устройство}` – «на связи», само исчезает при обрыве.
- Firestore `users/{uid}/sites/{точка}` – вся разметка точки: `planJSON` (план целиком, как читают кабинет и iPhone) и `layout` – то же полями, видно в консоли Firebase: размеры, магазин (углы), витрины и входы (сторона, концы, длина), штендеры, стеллажи и витрины-прилавки, зоны, камеры (название, псевдоним, цвет, тип, где витрина, место на плане, поворот, угол обзора, дальность, привязка). Уходит при каждом изменении плана или камер. Размеченный здесь план главнее облачного; правка в кабинете (позже) приходит сюда, прежний план на всякий случай сохраняется в браузере (`twin.plan.beforeCloud`). Камеры этого компьютера – в `…/cameras`, подложка плана – в `…/assets/background`.

Идёт демо (раздел «Демо») – уходит демо, как с iPhone: `meta.demo`, придуманные прохожие на плане, камеры демо, счётчики с запуска и сам план демо (`demoPlan`, только при изменении). Здесь ничего не идёт, а точку сейчас передаёт другое устройство (iPhone с демо или подсчётом, другой компьютер) – этот компьютер его не перебивает и при выходе не гасит.

Включается в «Профиль» → «Цифровой двойник в облаке» (по умолчанию включено), там же код точки (`main`; если магазинов несколько – на каждом свой). Видео никуда не уходит – только координаты и счётчики.

## Записи

«Записать двойника» (во время мониторинга или демо) и «Сохранить двойника» (после видео) сохраняют людей на плане по времени вместе с планом – раздел «Записи»: проигрыватель с перемоткой и скоростью ½×–4×, тепло до текущего момента, зоны (заходы, среднее время, максимум одновременно), скорость людей; запись по видео хранит копию ролика и показывает его в плавающем окне синхронно с планом. Записи лежат в этом браузере (IndexedDB), их можно переименовать и удалить.

## IP-камеры

Браузер не умеет искать устройства в сети и читать RTSP, поэтому вместе со страницей работает небольшой локальный мост (`bridge/`). Он запускается сам внутри `npm run dev` и `npm run preview`, а для мини-ПК у витрины есть отдельный запуск без сервера разработки:

```bash
npm run build
npm run serve        # http://localhost:8787 – страница + мост IP-камер
```

Как в iOS-приложении:

1. «IP-камера» (на вкладке проверки) или «Найти или подключить IP-камеру» (шаг «Камеры» → «Добавить камеру») → «Найти камеры». Мост ищет ONVIF-камеры (WS-Discovery на каждый адрес подсети /24) и устройства с открытым портом RTSP 554/8554.
2. ONVIF-камера: вводите логин и пароль камеры – Mantis сам получает адрес дополнительного потока (GetCapabilities → GetProfiles → GetStreamUri, пароль по WS-Security и HTTP Digest) и сразу подключается.
3. Камера без ONVIF: выбираете марку (Hikvision, Dahua, Uniview, TP-Link) – подставляется путь потока.
4. Или вводите адрес `rtsp://…` вручную, есть примеры.

Поток декодирует ffmpeg: он ставится вместе с `npm install` (пакет `ffmpeg-static`), либо берётся системный (`brew install ffmpeg`). Мост отдаёт странице последний кадр JPEG, при обрыве сам переподключается, неиспользуемый поток закрывает через минуту. Мост принимает запросы только с этого же компьютера; видео и пароли не уходят в интернет. Адрес и пароль камеры сохраняются в этом браузере – пилот после перезагрузки подключается к камере сам.

Если камеры в другой подсети, адреса для ONVIF-поиска можно добавить: `MANTIS_EXTRA_PROBE=10.0.5.20:3702 npm run serve`.

## Mantis Агент – одна программа для компьютера у витрины

Для пилота у клиента не нужно ставить Node и запускать команды: всё собрано в одно приложение.

- **macOS** – `Mantis Agent.app` (Apple Silicon и Intel отдельно), **Windows** – `Mantis Agent.exe`.
- Внутри: страница Mantis с нейросетью, мост IP-камер и ffmpeg. Двойной клик – открывается браузер на `http://localhost:8787`. Повторный запуск просто открывает страницу.
- В разделе «Мониторинг» (итоги и шаг «Камеры») появляется блок агента: «Запускать при входе в систему» (macOS – LaunchAgent, Windows – автозагрузка в реестре пользователя) и «Выключить агента». После перезагрузки компьютера агент стартует, открывает страницу, и мониторинг продолжается сам.
- Слушает только этот компьютер (127.0.0.1). Журнал: macOS `~/Library/Application Support/Mantis Agent/agent.log`, Windows `%LOCALAPPDATA%\Mantis Agent\agent.log`.

Сборка (на Mac или Linux):

```bash
npm install
npm run agent                      # все платформы → agent/dist/Mantis-Agent-*.zip
bash agent/build.sh darwin-arm64   # только одна
```

На Mac приложение подписывается `codesign`. По умолчанию – без сертификата (ad-hoc): при первом запуске macOS попросит разрешить его в «Конфиденциальность и безопасность». Чтобы этого не было, подпишите сертификатом Developer ID и заверьте у Apple:

```bash
MAC_SIGN_ID="Developer ID Application: RSM IT (TEAMID)" bash agent/build.sh darwin-arm64
xcrun notarytool submit agent/dist/Mantis-Agent-macOS-arm64.zip --keychain-profile mantis --wait
```

Windows-версия без подписи: SmartScreen покажет предупреждение («Подробнее» → «Выполнить в любом случае»).

## Vercel (для тестирования)

`vercel.json` уже настроен: установка `npm ci --ignore-scripts`, сборка `npm run build`, папка `dist`, заголовки для многопоточной нейросети (COOP/COEP) и тип `application/wasm`. ## Хостинг: www.umelcy.com/app/mantis/

Сборка не привязана к адресу (все пути относительные), поэтому одна и та же `dist/` работает и в корне сайта, и в подпапке, и внутри Mantis Агента.

1. `npm run build` → папка `dist/`.
2. Всё **содержимое** `dist/` (вместе со скрытым `.htaccess`) – в папку `app/mantis/` на хостинге, чтобы `index.html` открывался как `www.umelcy.com/app/mantis/`.
3. Адрес без «/» на конце (`…/app/mantis`) страница сама поправит на `…/app/mantis/`.

Что нужно от сервера (на Apache это делает `.htaccess` из сборки, нужен `mod_headers`):

- заголовки `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp` – без них нейросеть считает в один поток, медленнее;
- тип `application/wasm` для `.wasm`, `text/javascript` для `.mjs`;
- HTTPS – без него браузер не даст камеру компьютера.

nginx:

```nginx
location /app/mantis/ {
    alias /var/www/umelcy/app/mantis/;
    index index.html;
    add_header Cross-Origin-Opener-Policy same-origin always;
    add_header Cross-Origin-Embedder-Policy require-corp always;
    types { application/wasm wasm; text/javascript mjs js; }
}
```

На хостинге нет моста IP-камер (`/api/…`): на сайте работают камера компьютера/USB, видео и вход в профиль. IP-камеры – через Mantis Агент на компьютере у витрины. Сборки Агента для Windows и Mac (Apple Silicon и Intel) собирает «Деплой в прод» и кладёт на сервер – кнопки «Скачать» ведут на https://mantis.rcmit.ru/downloads/ (подробнее – [docs/agent.md](docs/agent.md)).

## Сверка с эталоном

`npm test` прогоняет `tests/fixtures/golden.json` (тот же файл, что в iOS-тестах; получен `python/tools/make_golden.py`):

- аналитика на треках ultralytics даёт те же счётчики, что Python;
- ByteTrack из сырых детекций повторяет ID ultralytics на всех 600 кадрах;
- полный путь «сырые детекции → трекер → подсчёт» совпадает с итогом Python.

Проверка в браузере (Chromium, WASM) на самом ролике `work/mantis_test_clip.mp4` дала те же счётчики, что Python: прошли 5 (→ 2, ← 3), притормозили 0, посмотрели 4. Нейросеть в браузере видит кадр чуть иначе, чем OpenCV (другой декодер и масштабирование), поэтому на других видео итог может отличаться от Python на одного-двух человек.

## Ограничения

- Видео с iPhone в HEVC (.MOV) открываются в Safari и Chrome на Mac. В Firefox и части Windows-браузеров HEVC может не открыться; тогда помогает перекодирование в MP4 H.264.
- Скорость: на слабом 2-ядерном сервере без видеокарты (WASM) – около 650 мс на кадр, 40-секундный ролик при 15 кадрах/с считается ~10 минут. С WebGPU на Mac с M-процессором должно быть в разы быстрее; время на кадр видно прямо во время анализа. Для быстрой прикидки можно поставить 5–10 кадров в секунду в «Порогах».
- Тепловая карта есть на плане двойника; тепловой карты поверх кадра и PDF-отчёта пока нет: они есть в iOS-приложении.
- Двойник, его статистика дня и записи хранятся в браузере (localStorage, IndexedDB) – в другом браузере или на другом компьютере их не будет.
